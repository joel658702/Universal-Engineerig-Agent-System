## 5. Sustitución `.sh` → `.py` (requiere tu visto bueno)

Los scripts pedidos llevan extensión `.sh`. En este entorno **no pueden ejecutarse**:

- `bash` del sistema → WSL no provisionado (`E_ACCESSDENIED`).
- Git Bash (`C:\Program Files\Git\bin\bash.exe`) → `fatal error - couldn't create signal pipe, Win32 error 5` (el sandbox bloquea named pipes).

Entregar un `.sh` no ejecutable y declararlo probado violaría R4 y R5. Se crearon equivalentes en Python, con el mismo contrato y verificados:

| Pedido | Entregado | Verificado |
|---|---|---|
| `verify_security_policies.sh` | [`scripts/verify_security_policies.py`](scripts/verify_security_policies.py) | sí (ver evidencia UEAS-004) |
| `verify_evidence_format.sh` | [`scripts/verify_evidence_format.py`](scripts/verify_evidence_format.py) | sí (ver evidencia UEAS-004) |

Si el CI es Linux, añadir dos wrappers `.sh` de tres líneas es inmediato — pero se declararían `not_run` en este entorno hasta ejecutarlos allí.
